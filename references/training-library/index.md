# 四层动作与训练单元库

按**能力维度 → 领域 → 动作族 → 具体条目**选择。能力词表由capabilities.json定义；7个领域、101个动作族及336项目录由assets-v3.json统一保存。目录＝286个动作＋50个训练单元（含2个蛙泳仅参考条目）；库内另有16个历史运行适配项与10个课部件（热身、整理、滚压、拉伸、轻松游、技术游等）不参与动作选择，按段序规则调用。run_time_trial仅保留目录，不进入训练计划。目录有某项工具不代表用户或当前周期已发展该能力。

| 层级 | 选择任务 |
|---|---|
| 能力维度 | 本阶段发展、维持或暂缓什么能力 |
| 领域 | 准备与恢复、功能性力量、爆发力、速度与移动、跑步、游泳、能量代谢 |
| 动作族 | 找承担同类任务的工具，比较可用条件与投入回报 |
| 具体条目 | 选择器材、姿势、技术版本和适用剂量，落实到本课 |

catalog.json是同一四层库的查找摘要；完整定义在assets-v3.json。exercises.json与training-units.json提供执行接口，共362个ID，包含75个历史ID，其中41个为额外兼容入口；课表使用注册ID。具体别名保持原动作语义，不能让旧泛称替代不熟悉的新技术。generic准备或整理须展开具体内容，不能把整个分类当动作。

## 按需读取

先读本页及[选择与收益](selection.md)，再用`scripts/select_assets.py --domain B`、`--family "水平推"`或`--query landmine`筛选简短列表；`--id 具体ID`读取少数完整条目。不要每次把整包动作库载入上下文。没有参数时列领域；ID不存在则报错，不能临时编造。

核对exercise_definition、equipment_options、prerequisite、selection_conditions、requires_mastery、stop_condition及替代关联，再选择[剂量策略](dose-guides.json)。库内default_dose是满足条件的明确起点；本次剂量由起点、阶段任务与整周负荷确定，不能把默认数字照抄给所有人。dose_domain标明参数接口与任务边界；machine_check字段由脚本核对，文字条件和无结构接口的参数仍由设计者判断。

## 等级与不同条目形态

同一动作族内、任务与条件可比时，使用条目已有的基准、退阶、进阶和Phase阶段链。器材或任务改变的分支保留独立ID，不自动获得更高等级或负荷等效；阶段链按family.phase_sequences承接，不把目录行序当难度排序。

动作展开组次、时距、强度与恢复；训练单元展开实际工作、主动恢复、纯休息或出发间隔；课部件依据component_spec的触发条件进入对应课段，不能额外生成一个重复训练日。混合走跑与变强度单元按requires_segment_expansion拆出真实工作段：走路不计跑量，质量课中的轻松恢复仍计轻松跑，池边休息不计泳距。

## 周期使用与维护

完整功能课依次落实具体区域的滚压与呼吸、拉伸、纠正和活动度、激活、动作技能、快速输出、力量组合及能量代谢决定；局部针对性支持嵌入已有环节，周末放松按[support-and-correction](../support-and-correction.md)安排。需技术前置的动作选已独立掌握版本；低技术基础准备可在器材可用、无已知相关限制时按正常完成开明确处方，不编造已掌握观察。

coverage.json核对11项能力及领域任务的可用工具与边界，不能替代本周实际模式和剂量检查。库更新后运行`scripts/validate_library.py`，核对定义、关系、阶段链、剂量接口、来源清理和运行ID；检查通过不认证所有动作适合每个人。新锐痛、明显失控或异常出现时结束相关内容，再修正受影响处方。


蛙泳6个可编排条目与2个仅参考条目的准入、计量和反馈见[游泳技术契约](../swim-technique-contract.md)。来源只用 evidence_refs 引用独立的[来源登记](../swim-technique-evidence.json)，不在动作说明中复制教材。
