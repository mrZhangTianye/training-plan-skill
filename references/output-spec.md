# 输出规范

本文带公斤数的格式演示均为重新构造的合成数据，不是任何人的训练记录，也不是默认处方。真实计划只保存经授权提供的有效记录与实际日期。

使用可编辑Markdown，数据与展示分开。课表直接回答怎么练：每项给确定的组数、次数、时间或距离、强度、恢复和执行要点；不能让用户在一个宽范围里自行选处方。**力量组合的强度格必须说清这一组的重量怎么定**：有 TR 就写数值（`RPE7 · 42kg`），没有就写目标努力度＋选重方法（`RPE7 · 首组偏轻现选`），表里只写数值——`RPE7 · 42kg`／`RPE6 · 自重`／`RPE7 · 粗弹力带`／`25kg/手`。**「约余N次」、`TR 36kg×8（合成示例，非真实记录）` 这类溯源括号、「待补」说明，一律不进表格**（组次与日期的溯源留在 plan.json 的 `reference_weight_basis`）；自重、垫上类动作不写公斤数；**弹力带／小环带是负重选择，不是器材**，按阻力档写（粗／细／无），与公斤数同属「计划」列的载重档，粗细换档＝重量选择。参考重量不是必须完成的指标，但课表里必须能照着定重量：要么是 TR 数值，要么是「目标 RPE＋选重方法＋预设休息」三样齐；只写一个光秃秃的 RPE、让用户自己猜重量，算不合格。

**参考重量的取值顺序**：① 用户历史训练记录里的实做重量（用户自己的记录文件或知识库，含实际组次与日期），取到后表里只写数值（`42kg`），带组次与日期的溯源写进 plan.json 的 `reference_weight_basis`（`TR 42kg×6（合成示例，非真实记录）`）；② 取不到历史时才用动作库的 `default_dose`／建议重量，并注明来源为库建议；③ 两者都没有，就按目标 RPE 写「首组现选＋调重规则」（明显多于／少于目标余次数各怎么调），公斤数留空由执行记录回填，不写「待补」占位。三类东西分清：技能里动作库的建议是通用默认值；用户历史里的 TR 是他真实做过的重量；课表的参考重量按此顺序从两者取。库建议只兜底，不能盖过真实 TR。

整体简要展示目标、阶段、周安排与预设递进。阶段用横向各周剂量表显示实际变化。周概览列日期、训练、跑泳单次总量和整课时长，另用一行汇总跑泳周总量及计划有氧当量；随后直接展开各课。单次展示日期、整课时长、跑泳单次总量、一个小目标以及分块处方表。调整展示实际改动及后续影响。实际表现与目标处方分开，未报告值不填零。

总览与阶段课表标识草案、执行版或虚构样稿、版本及覆盖范围（阶段与总览的标识行同时承载「哪些周尚未展开执行课表」的警告，不可删）。单次课表与周课表不重复标识草案或版本。执行版先完成后台校验；用户只看到明确训练建议与必要假设，不显示内部审查表、能力标签、用户记录、检索过程或外部引用。影响执行的未解决问题须在建议中说明，不能隐藏后标为执行版。

每个动作或游泳组独立列行。力量组合用A组、B组、C组分块，行内用A1/A2/A3表示执行顺序。各动作保留真实组数：相同组数可以写3轮，不等组写3／2／2组并给明确组序，不能为了统一循环增加核心剂量。表列为动作、剂量、强度、恢复；剂量简写3×8、2×20秒/侧、6×100米，力量强度写RPE及剩余规范次数的选重锚点。每堂力量课只解释一次：表中恢复是同一动作下次开始前的恢复，穿插动作计入其中。滚压、拉伸可以合并相同处方的部位，但名称或必要提示必须完整列出区域/动作及每侧剂量；**拉伸循环、纠正、激活、动作准备、动作技能各压成一行**——动作列用 `名称 剂量｜名称 剂量…` 把段内全部动作串在一格（剂量只写组次/时长，不重复质量提示），计划列写段时长，要点列只写段名。

水中名称使用本课实际泳姿与任务，例如“自由泳：侧转换气”“自由泳：基础耐力”，通过item.display_name覆盖通用资产名；不改变资产本身适用条件。陆上直接列胸椎旋转、肩胛墙滑等具体动作。力量课中已声明的DUP锚点应在两课和阶段剂量表中直接可比较，不以标题代替次数与强度。

只保留影响执行的简短提示，例如具体准备动作、泳姿、纯休息或出发间隔。后台的cue、dose_basis、作用、长段notes和检查结论不逐行输出；必要提示放execution_note。输出不重复讲解已熟悉动作。异常处理保留一条短规则；具体已知限制仍必须明确。

强度列写出本行实际执行锚点，例如快速且可控输出、可连贯交谈的轻松跑或保持技术的可重复较强泳；不能用“按本行要求完成”等循环指代充当强度指导。

## 单次与周表的阅读顺序

环境、限制与规则说明不进单次课表：草案/版本标识、已知限制段落、「明显不适或动作失控时停止」类免责句、「未标开始时刻的单课时间灵活安排」、配对／三联组序的规则说明，都不出现在单次与周表。周表保留一行周总量与一行有氧当量——下游脚本按这两行分段，不可删。

环节固定编号，照 Table 11.10 段序写死：1滚压与呼吸 2拉伸循环 3纠正 4激活 5动作准备 6动作技能 7速度 8增强式 9药球 10力量 11能量代谢。本阶段不排的段保留编号位置不出（阶段1不排7），编号不因跳过而重排。力量组合编为10-A／10-B／10-C，条目仍用A1／A2／A3。

**非力量模块不列强度列**——准备、纠正、激活、动作技能、能量代谢的强度恒为「低负荷、幅度可控」这类零信息量表述。恢复并入剂量格写成`6×50米（休20秒）`，准备类表压到动作｜剂量两列；只有力量组合保留强度（RPE）与同动作恢复。必要提示列只留剂量与强度表达不出的内容（首组选偏轻负重、每次落稳重置、脚跟贴地），不复述剂量或强度；表头仍叫「必要提示」。

周表先写一次跨全部力量课完全相同的模块（标题「每日重复部分（每次力量课都一样）」），各日只列变化部分并注明「当日只列变化部分；1、2、4、5、6、8、9、11 见上文每日重复部分」。判定「相同」时必须忽略session级动作id，否则每天都会被判成不同、去重失效。

阶段视图逐行按周列剂量，不做「四周恒定」折叠——跨周对齐必须一眼可见。

跑课明确单次总跑量（公里或米），泳课明确单次总距离（米），与处方各段的累计量一致。时间型跑课没有可靠配速依据时展示总跑动分钟并注明距离未估算；有依据的预计公里数标明估算。总量包括实际跑动或游动的热身、恢复段与冷身，走路、纯休息和陆上准备不混入距离。

周跑步汇总另用简短一行列出轻松与非轻松跑段的计划分钟和占比，节奏、间歇和短快段分别列明；按全部实际跑动分钟计算，与单次跑动时间一致；质量课中的轻松段仍归轻松。总公里数另列，不混用距离与时间占比，也不把计划分配写成已经验证的实际表现。

有氧汇总写“计划净量”和“计划中等当量”，不冒称已经完成或实际强度已测定。轻度运动单列不计健康当量；没有强度或净分钟依据时写未核定。力量整课、拉伸、转换与纯休息不自动计入。对低起点计划注明当前桥接周及最终目标，不把每个早期周都强行凑到同一时长。

## 周课表（记录式，标准形态）

一个文档 = 一周。第一行 `# W1 训练计划（2026-01-05 ~ 01-11）· 本周定位一句话`，第二行给本周定位与总量，紧接着两个固定行：`本周总量：总泳距2650米。`（跑泳都没有时写 `本周总量：本周无跑泳剂量。`）与 `计划有氧当量：125.6 分钟（周下限 60 分钟）。`。这两行由 `endurance_stats` 与 `aerobic_stats` 直接算出，不手写；单次量必须落在每节标题的括注里（泳课 `（约55分钟 · 总泳距1250米）`，跑课 `（约45分钟 · 总跑动16分钟；预计总跑量3.2公里）`，跑泳都没有时只写时长）；别把走路、纯休息、陆上准备算进距离。随后每天一节 `## 周一 1/05 — 力量 A（髋主导 + 水平推）`，节内一张表铺到底，不按环节切多个小表。**每天固定块序：标题 → `本次小目标` 段 → `节奏与恢复` 段 → 表**（只有力量日有中间两段，游泳／放松日直接标题接表）。`节奏与恢复` 一整课只讲一次：离心／向心节拍 + 配对与三联按轮做（轮内换项≤1分）+ 一轮做完的休息，不在表里逐行重复：

`| 序号 | 动作 | 计划 | 要点 | 表现 |`

⚠️ **表头行不能省**：生成表格时第一行必须显式写 `序号／动作／计划／要点／表现`。任何把首行当表头处理的渲染器（Markdown 表格、Notion table、HTML `<table>`、Excel 导入）都会把第一条数据吃掉，看起来就是「表格没有标题」。生成后读回断言 `rows[0][0] == '序号'`。

- 序号：当天连续编号，1 到末项；**配对组／超级组共用编号加字母（1-A、1-B、1-C）**——同组内轮转的两三个动作是同一格，不各占一个序号。
- 计划：剂量＋强度＋重量，如 `3×12 · RPE6 · 22.5kg`、`3×8 · RPE7 · 42kg`、`3×12/侧 · RPE6 · 自重`、`3×8 · RPE7 · 粗弹力带`；时间型写 `2×25秒`、`15分钟`，距离型写 `3×2×50米`。**「计划」列只有四样东西：组数、次数、RPE、重量**（时间型就是时长、距离型就是距离）；`约余N次`、括号说明、「待补」一律不留。准备类五个段（拉伸循环／纠正／激活／动作准备／动作技能）的动作格只写动作名，剂量挪进计划格写成 `1×5/侧｜1×5/侧｜1×10/侧`；滚压行的计划格写部位与时长（`臀髋、腘绳、小腿、肩后、内收、股四头各20秒/侧；上背30秒`）。**剂量后面不加质量／呼吸／姿势描述句**——`2×5 · 快速释放，保持每次投掷质量` 只留 `2×5`，`1×3 · 呼吸平稳、自然` 只留 `1×3`，`15分钟 · 呼吸提高，能说话但难唱歌` 只留 `15分钟`，`2×25秒 · 躯干位置稳定、自然呼吸` 只留 `2×25秒`。解释性括号（`（历史同类：… 15kg 基准）`）、`待补` 说明、「约余N次」、`TR 42kg×6（合成示例，非真实记录）` 这类溯源括号一律不进表格——TR 的来源与日期写在 plan.json 的 `reference_weight_basis`。
- 要点：**只写环节归属**（段名或组合名，如 `滚压与呼吸`、`前置组合 · 斜向推与上肢活动度`）。恢复不再逐行写——整课只在 `节奏与恢复` 段讲一次；**技术提示句不进要点**（动作描述、呼吸语、质量语一律不写）。**单元格里不留 `｜` 后缀**：`增强式 ｜ 组间2分`、`药球 ｜ 组间1分`、`力量配对 · 单侧膝主导与垂直拉 ｜ 同动作恢复2.5分`、`后续三联 · … ｜ 转项≤1分 · 同动作恢复1分`、`能量代谢 ｜ 主段15分钟…`、`陆上准备 ｜ 前后各8次`、`主组：递减休息 ｜ 12趟…` 一律截到 `｜` 之前。同一组合的每一行写**同一个组合名**，不逐行改写成不同描述。没有例外——增强式的平台高度与落地要求也一起删（它们是动作描述，不属于环节名）。
- 表现：常驻留空，供练完回填（重量组次／余力／当晚反应／次晨反应，相关部位分别记录）。**碰上才补注，不常驻**：`设置改变（档位5→6）`／`行程缩短`／`明显变慢`／`不适`——只有发生时才多写几个字，不新增固定列。第 4 阶段容量课做跨周比较时按**同课型、同组序、第 1–2 组**对照（末组行程缩短照记，那是当次质量不是趋势）；器械设置变了的那一周不给趋势判据资格。**练完的记录写进回填文件后它就是真源**：重渲染前必须把它合并进来（`表现回填.json`，含 `课`+`当前动作名`+原文，渲染器 `--feedback` 读取）；**禁止用空列覆盖已填回填**；改名只在文件的「当前动作名」做映射，原文照抄；匹配键必须是「课次+动作名」——同名准备动作每天都有，只按动作名会串纪录。**合并行的表现**把段内各动作的回填合成一格：相同的只说一次，不同的按动作名列出（`完成；半跪髋屈肌拉伸：忘了 跳过了`）。
- 末节 `## 本周要点`：一天一个项目、踝承载、本周不可让的地方。

记录式周文档**不折叠重复模块**——每天完整列出（准备段也照排），因为这份文档同时当记录表用；环节式视图里的「每日重复部分」只用于内部审查。生成：`python3 scripts/render_weekly_log.py plan.json --week 1 --output 第1周训练计划.md`。就绪门按周判：该周 `detail_status` 为 `scheduled` 且全盘无错即可正常出文档，其余周还是骨架不影响这一份；未排期的周要加 `--draft`。

课程与阶段参数使用计划内真实ID；示例为W01-F1和B1，其他计划按其ID替换。包内示例是虚构草案，上述渲染命令对它使用时加`--draft`。errors先修正，insufficient_basis按缺口补判断；review_items中的具体取舍须在design_context.review_resolutions逐项处理。已有条件与明确请求可支持selected，不伪造用户确认。自校验通过表示数据和确定性约束成立，训练刺激与递进的合理性仍需Skill完成判断。

## 载重档要三个字段一起写（少了就不显示）

一个重量要在 JSON 里落三处，各喂一条渲染路径，缺哪处就在那条路径上静默消失：

- **`dose.load.reference_weight_kg` ＋ `reference_weight_unit`**（`per_hand`／`total`）：数据层公斤数。总览与环节视图读它，渲染成 `9kg/手（参考）`。`per_hand` 表示每手、`total` 表示总重（壶铃、药球、双手器械），写错单位会让表格把总重标成每手。
- **`dose.load.page_load`**：周课表「计划」列实际显示的那一格，值直接是成品文字——`9kg/手`、`自重`、`粗弹力带`、`16kg壶铃（双手）`、`6kg药球`、`22kg/手`。**只填 kg 不填 page_load，周课表整列重量消失**：校验全绿、总览也有数，最像「已经补齐」的一种漏。
- **`dose.load.reference_weight_basis`**：溯源。kg 非空时必须**以 `TR ` 开头**（`TR 9kg/手×6（合成示例，非真实记录）`），否则校验报「加载动作缺选重处方」；自重／弹力带没有 kg，就把负荷方式写在这里（`示例档案设定：粗弹力带档`），不要留「待补」。

**自重与弹力带一律 kg 留空**：kg 填 0 或体重会被当负重算进负荷线；负荷方式靠 `page_load` 与 `description` 承载。有 RPE 的条目还必须同时给 `selection_method`（kg 空 + 有 RPE 时校验要求它），否则报缺选重处方。

**示例重量只做条件一致性核对**：比较同一动作数据，先固定器材、单/双侧计量、动作范围、次数、目标 RPE 与记录情境。次数更多或 RPE 更高都不单独推出必须更重，跨动作重量也不能直接比较。来源不明的重量不补成真实 TR；合成示例须标注，真实计划按有效记录与首组选择方法定负荷。此处只规定样例一致性，不增加处方公式或自动修改资产数值。

**合并行不显示载重档**：激活、拉伸循环、纠正、动作准备、动作技能这五段压成一行，只渲染动作名与段时长，`page_load` 不进表。这类条目的负荷方式靠动作名承载（`小环带深蹲`），不要指望计划格显示「细环带」——交付时说明这一点，别让它被当成没补齐。

**核对三行**：

```sh
python3 scripts/validate_plan.py plan.json            # errors 必须为空，缺选重处方会直接报出来
grep -c 'kg/手' 第1周训练计划.md                       # 与 JSON 里 per_hand 条目数对不上＝漏了 page_load
grep -c '待补' 第1周训练计划.md                        # 草案示例也应为 0
```

再把每节力量课的 `page_load` 逐条比对导出文件（缺哪条列哪条），不要只数总数——总数对上而某节漏一行是这类漏的常见形态。

## 文件交付

完整12周导出计划总览和12份周课表；独立4周导出阶段总览和4份周课表；独立周仅一份周课表；单次按需导出。周课表包含完整单次，不默认重复导出单次文件。**用户问「第N周计划」时就只交那一份文档（第N周训练计划.md），不主动附总览、阶段视图或单课文件**——多文件是被要求时才给，一次一周只给一周的东西。用户仅要求总体方向时可先交总览；远期仅概要须显著标注尚未展开，不能称完整执行版。

整包导出：`python3 scripts/export_plan.py plan.json --output-dir 课表目录`；草案加`--draft`。同日多练按实际开始时间排序，单日一课未定时刻时写时间灵活安排，不虚构具体时段。
