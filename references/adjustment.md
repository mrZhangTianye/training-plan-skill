# 反馈与变更

## 默认继续

没有新异常或条件变化时，默认正常完成前期训练，按预设剂量展开下一周或进入下一阶段；**「进下一阶段」也是加量，先过[加量闸门](limitations.md#六疼痛与负荷的判定310)**。不索要逐次日志、证明或测试，也不虚构实际完成情况。**这不是「先反馈才能推进」**：无反馈就按预设往下走，反馈只是调整的触发条件，不是推进的许可证。预设递进是原计划的一部分，不是每次都要重新申请的修改。

## 三种入口

外部计划：提取目标、结构、剂量和适用起点，由Skill判断保留、替换、削减或重组，给出明确适配意见。已授权直接适配时不另设无必要确认。

主动修改：时间、设备、偏好或明确要求就是有效约束。区分只影响本次与持续条件，不把“今天没时间”扩展成整个周期都无时间；无需用户证明原计划失败。

表现反馈：接收用户自述的重量、次数、用力程度、时长、配速、距离、质量、身体反应等。记录日期与原始表述，不把未提供值补成零，不把主观体验改写成诊断。

**回填是持久真源**：用户在页面上写下的原文，不因重新渲染、重排动作或改名而消失；重渲染前先合并 `表现回填.json`（按课次+动作名），空列不得覆盖已填值。

## 跨项目取舍：谁定、怎么定

时间变化落到多个项目上（能练几天、每次多久都变了）时，**不由本包替用户决定砍哪个项目**。四步，顺序固定：

1. **确认变化**：能练几次、每次多久、影响哪几周。已有条件直接复用，不重复问一遍。
2. **给推荐方案**：写清力量、跑步、游泳各分多少时间、各保留什么、各减什么、为什么这样分，以及对本阶段目标进度的预计影响。方向可行时再给 1–2 个备选，每个备选同样标代价——不把备选写成「也可以」，那样等于没给选择。
3. **用户选择**：用户定项目优先级（例如「我更想保留跑步」）。组次、RPE、休息、组距、配速这些仍由本包算清楚，不交给用户决定。用户定的是**减去多少**，不是**限制还算不算**——已有依据的身体限制进候选方案后不被偏好推翻：「我更想保留跑步」可以换掉时间分配，不能换掉「已声明的限制」这类条件（例如使用者已声明的 `no_impact`：跑跳限制按部位、风险及已有专业要求执行，仅当适用指南或医嘱要求时才以影像愈合为条件；医嘱明确禁止跑跳的一律不排）。
4. **重排受影响课表**：不改阶段数量、阶段长度与总周数，保留已执行历史，不强制追补漏掉的课。时间预算撑不住原目标时把差距写明白，不用「尽量」盖过去。

**各专项的缩减顺序表只是设计参考，不自动变成「必须砍哪个项目」的判决。** 它用在第 3 步选定方向之后算具体剂量，不代替用户选方向。

推荐、备选、用户选定项与预计代价一并记进 `review`（`topic=load_recovery`），下次能看出这次为什么砍这个而不是那个。

## 明确调整意见

| 情况 | 默认处理 |
|---|---|
| 熟悉力量规定次数明显偏重 | 先减当次负重以接近原目标RPE，保留主要任务；确实无法完成再减少该动作剂量，不提高目标RPE |
| 规定次数明显偏轻且质量稳定 | 以最小合适负重步进接近目标RPE；原定次数递进照计划，不为一次轻松额外叠加组数 |
| 一次完成困难或短时疲劳 | 优先调整当次及直接相关的下一课，不立即重排整个周期 |
| 多次同类课困难或跨项目疲劳 | 核对目标强度、实际剂量与局部重叠，先降低次要项目成本或撤回最近增加的变量，给出本周与后续具体改量 |
| 跑步或游泳体感比计划明显更重 | 保持原强度任务，先慢一点、延长恢复或缩短工作段；不要为参考配速和距离硬撑 |
| 表现顺利且没有修改要求 | 继续预设递进，无需加码或再次确认 |
| 新的明确疼痛、失控或异常 | 停止相关内容、确认影响和已有专业要求；可保留不受影响训练，不自行诊断或授予许可 |

**「恢复得快」与「练得不够」是两件事，不要读反**：

- 用户说「睡一觉就好了」→ 读成**恢复系统正常**，不读成「还能加」。一晚恢复的是外周疲劳（肌肉），中枢（神经）的账要 1–2 天才结清；把「不酸不困」当加码依据，会连着两周好看、第三周塔。
- 用户说「练完不酸」→ 不证明刺激不够。酸痛取决于离心量与动作生疏度，不取决于强度；硬拉练完第二天不酸，可以是刺激到位。别为了「想练到酸」去加组或改离心。
- 判断一次狠练是否成立，看**几天恢复过来**：3 天内→底子好、按计划走；5 天还沉→上一轮透支，下一个推进点不加；一直缓不过来且晨起心率偏高→先查睡眠与蛋白摄入，那本来就不是加量的时间点。
- **「上一周练得很狠」不是本周该加的理由**：它是把次周排成引导周（低一档组数）的理由。狠练的收益在恢复期兑现，不在当天。

反复问题没有统一医学次数阈值。Skill判断调整层级并说明原因；缺信息只问会改变当前决定的关键项，不要求完整日志后才采取可行调整。

## 中断与重入

缺一次不挤进休息日补课，优先沿日历继续；若缺的是关键刺激，则说明顺延或替换哪一课及其代价。连续中断时根据停练原因、最近同类暴露和当前能力选择首课，默认先回到熟悉动作和近期能承受的剂量，再给明确后续步进。不得机械按天数诊断退训或强制重开第1阶段。

暂停或退出保留历史。恢复到指定阶段时检查该阶段确实需要的动作、能力与负荷条件；条件仍成立即可继续，不设日志或测试通关。

## 关联与版本

检查修改课的前后课、周总量与局部重叠、替代动作的目标和剂量、后续递进起点、上层摘要及阶段目标。保留有效刺激，不能把“减量”自动变成所有项目同时低强度。只修改受影响实体，已完成训练保留历史。

处方修改另存版本，用实际差异生成变更结果，再写原因与关联影响。没有原计划时请求能定位的原课表，不假装做了局部比较。修正后重新检查时间、组合恢复、剂量与后续进阶，向用户给更新课表及简明理由，不展示后台自评分。

已有恢复取舍按当前review_requirements的context_hash核对。相关实质负荷、时间或预算改变时，Skill重新判断并更新对应决定与理由；历史处理不自动授权新负荷，不为此要求用户提交日志或再次确认。

改跑段或泳段后重新汇总整堂与整周总量、跑步强度分配、健康当量及时间预算。池长改变时修改结构化pool字段或本课覆盖值，重排不合池长的组距；泳速或节奏估算改变时同步工作时间与出发间隔。换动作或跨周移动时沿用同一任务的稳定ID，实际任务改变才换ID，不靠行序保持阶段对应。
