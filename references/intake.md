# 通用信息收集

## 先过画像关

进编排前先过这一道，不过就不往下走：

- 目标是某场比赛、名次或成绩达标 → 超范围
- 要备赛／要专项峰值／愿为某场比赛调整训练 → 超出画像（专项化训练者）。**单纯跑 ≥4 次或泳 ≥3 次不算**——课次多只是需要排布，不是超范围
- 需要诊断、影像判读、康复处方 → 超范围

说明为什么，**不给“打折版”**：把这套骨架减量套给专项需求，既满足不了专项目标，又把综合训练的结构搞乱。

先复用已有对话和用户信息，按下面的问题模板收集缺口，可合成一轮简短问询。用户表达目标和自身情况；模型根据回答提出发展重点、项目分工和编排意见，用户可以修正。

## 问题模板

| 信息 | 问题模板 | 使用方式 |
| --- | --- | --- |
| 目标 | 这次主要想改善什么？例如全面体能、某项身体能力、生活任务或其他运动准备。 | 用户只说全面提高时，沿用长期六边形定位，由模型提出具体重点。 |
| 训练经验与近况 | 平时主要练什么？最近每周练几次，大致训练量怎样？ | 接受粗略经验与近期描述；需要定起点时再补问一个可重复完成的力量组次或连续跑游表现。 |
| 时间与条件 | 每周可安排哪些天、功能性力量每次多久？有哪些器械和场地？ | 复用已知日期与器材；同日两练才补问具体时段和间隔。 |
| 身体限制 | 有没有伤病、疼痛，或已经明确需要避开的训练？ | 保留用户已说明的限制和专业要求，具体受限任务进入编排；未报告限制仅记录自述。 |
| 必要的专项信息 | 根据本次项目询问实际执行需要的信息。 | 游泳按需问泳姿、池长、单课距离和连续能力；跑步按需问近期时长或距离；功能力量按需问熟悉的动作模式。 |
| 跑与泳这次的定位 | 跑步和游泳这次是想改善某个具体环节，还是大致练着、保持参与？每项每周能给几次、每次多久？ | 答“随便练练／保持”就按维持档排，不追问目标也没关系；答要改善时只补问会改动剂量的那一点。**角色不同不并成一道题问**，两项可以一个发展、一个维持。 |
| 其他运动（含球类） | 这次还会不会打球或参加别的运动？什么项目、每周几次、有没有固定日期？ | 没有就不启用球前 48h／球后 24h，也不出现在课表里；有就当作固定占用排进周结构，沿用已有球类规则，不另建一套编排。 |
| 功能力量频次 | 力量（功能性训练）这次想练几次？ | **不预设两次**：用户指定次数就照办；没指定按时间预算给 1–2 次并说明取哪一档、少掉的量落在哪。 |

体重与体成分是结果信息。用户有明确相关目标，或这些数据会改变训练设计时，再问身高、体重及近期趋势等必要信息。

## 追问与进入编排

已知信息直接跳过，回答粗略可以采用；回答模糊时，只补问会改变排课、起始剂量或动作选择的关键缺口。收到足够信息就给明确推荐，不把全面测评或日志上传当作排课前提。

这一层整理目标、训练经验与近况、时间场地条件、身体限制和必要专项信息，交给后续编排。发展重点和训练主次由模型根据回答提出，不要求用户先完成专业判断。

需要完整功能力量时，可一次简问熟悉的膝主导、髋主导、推、拉动作；接受用户列举或明确表示熟悉的常用模式，不索要逐动作证明。陌生复杂动作优先换成熟悉替代，不额外开动作教学课。单日一课可按每天可用分钟安排，具体时刻未知时写时间灵活安排。

不要求测最大重量、参加比赛、完成入门测试或每日提交训练日志。**但每个加载动作必须取到的是「选重处方」**：组次、目标 RPE／RIR、**选重方法**（首组怎么取、偏轻偏重怎么调），以及预设的休息单值。**公斤数不是必问项**——用户报过该动作训练中实际完成的重量×次数×日期（格式演示 `TR 36kg×8（合成示例，非真实记录）`，此数字为本文重新构造，真实记录使用实际日期，哑铃说每手还是合计、杠铃说总重）时写成参考重量；没报过就写清选重方法、留到首组现场选并记进执行记录，**不预先编公斤数，也不用「待补」当交付缺口**。**不索要 PR／1RM（极限试举）**，也不从 TR 反推百分比。不虚构个人重量、心率、成绩或测试分区。未知配速用呼吸、交流程度与主观努力给明确时长处方。

默认用户能完成建议中的训练，按预先安排递进。基线有限但足以安排时，选择熟悉动作和明确起始剂量，记录假设与后续修正办法，仍给可执行建议；只有影响是否能够训练、关键时间或器材条件的缺口才先补问。不能因缺少逐次执行证据把所有后续周冻结。

基础准备无需逐项熟练证明。对已注册、无需技术前置的低技术准备单元，在已有器材且无已知相关限制时，直接选择具体形式、部位、组次和总时长，保留正常可完成的假设；未知掌握仍记unknown，不能改写成用户已熟悉。有明确限制或形式需要较高协调、负重技术时再局部补问或选熟悉替代。不能因用户只列了主动作，就把软组织、拉伸或整层准备删除。

不收集起床、工作和进餐日程，不把时段固定成某类训练。用户主动提供恢复困难或生活条件变化时，作为调整输入处理。

先在推荐中说明项目分工、周安排、阶段方向和预设递进。用户直接要求课表或明确委托Skill选择安排时保存arrangement.status=selected，并在selection_basis说明请求；用户明确认可具体安排时使用confirmed。只讨论方案或存在关键缺口时使用proposed。用户明确要求先确认方案时先给方案；已授权结构与单次修改不重复确认。

## Playwise 0.3.24：已确认输入与安排原则

- 球种保留用户选择并包含「其他」，不以未列入例子为不支持。未知项目只按已知日程约束处理，不根据名称猜负荷或专项处方。
- 时长选项指功能性力量训练时长，不询问球类时长。已有球时长可参考；未知保持未知，相关总时长只能记未核定，不应因此阻塞其他可安排内容。
- 用户选择的力量、跑步、游泳频次结合固定球日、可用日期、器材及恢复约束综合判断。无法安排时列明冲突和可替换方案，不擅自降低频次或假装已排好。
- 单日双练不是普遍禁令。可行时安排并说明先后、恢复与注意事项；明确冲突时解释，依据不足时标待核定。不要以每周课次是否超过七次决定用户是否能双练。
- 文档中2小时、6小时属于不同情境的经验安排，不是通用医学安全门槛。不能只凭开始时刻差宣称课间恢复充分，不能为了核算间隔强制索取球时长。已有明确训练组合限制仍须检查。

以上是输入和安排原则；球日日期与明确重叠由独立校验处理，不代表此版本已自动验证所有球类编排、负荷或恢复。
